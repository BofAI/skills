# Twitter Digest 精简分诊、Passcode 与限流设计

## 目标

将 twitter-digest 收敛成只读的三流事实摘要：Mentions、Timeline 和 X Chat。产品只说明必须知道、必须处理、当前状态和数据缺口，永久停止生成或推荐任何回复内容。

同时修复首次没有 X Chat passcode 时的生硬配置体验，限制空会话页追踪和重复请求，并在收到 HTTP 429 后通过本地冷却阻止用户重复触发同一受限接口。

## 永久输出边界

Skill 不再生成以下内容：

- 中文或英文回复草稿。
- “可以这样回复”等措辞建议。
- 可复制的回复文本。
- 对 Mention、Timeline 或私信的回复改写。
- 用户要求发送时附带的替代草稿。

Skill 仍然可以报告客观状态，例如 `等待处理`、`回复状态未确认`、`消息请求需要人工查看`。消息请求的 X 界面导航属于必要操作说明，不属于回复建议。

即使用户要求回复或发送，Skill 也只说明它永久只读，不提供回复文本，不创建脚本，也不调用其他工具绕过限制。

## 精简日报结构

固定输出：

1. 今日必须知道。
2. 今日必须处理。
3. Mentions。
4. Timeline。
5. 私信。
6. 数据缺口。

数量上限：

- 今日必须知道最多 5 条。
- 今日必须处理最多 10 条。
- Mentions 最多展开 5 条重要内容。
- Timeline 最多展开 5 个主题。
- 私信只展开确定等待处理的会话、消息请求和必要的覆盖说明。
- 普通内容和噪声只显示计数，不逐条展开。

删除重复总结、原始接口统计、请求预算、内部停止原因、没有行动价值的逐条 Timeline 和任何建议草稿。未知历史会话有已知参与者时只显示 `曾经收到过消息：@sender1、@sender2`，不添加技术解释或操作建议。

只有数据源状态为 `complete` 时才能断言没有待处理内容。`partial` 或 `unavailable` 只能报告已检查数量和数据缺口。

## Passcode 配置状态

### 已配置

跳过输入并只显示：

```text
X Chat 已配置，跳过 passcode。
```

### 尚未设置 X Chat passcode

当自己的公钥记录不存在或没有 `juicebox_config` 时，不再显示英文 SDK 错误。Terminal 显示：

```text
你的 X Chat 还没有设置 passcode，因此暂时无法读取加密消息。

请先在 X 中打开「消息」，按照 X 的提示开启 X Chat 并设置 passcode。
设置完成后，回到这里重新运行安装或配置即可。

按 Enter 打开 X 消息页面，输入 q 暂时退出。
```

只有用户按 Enter 时才打开 `https://x.com/messages`。配置程序不尝试代替用户操作 X，也不轮询等待设置完成。

### 输入 passcode

Terminal 显示：

```text
请输入你在 X Chat 中设置的 passcode。
它只用于本次解锁，不会保存，也不会显示在屏幕上。
```

### 解锁失败

同一次配置允许最多 3 次本地输入。错误信息不包含 traceback、Chat XDK 内部错误、密钥记录或 Juicebox 内容：

```text
没有成功解锁 X Chat。
请确认输入的是 X Chat passcode，而不是 X 密码或 OAuth Client Secret。
你可以重新输入，或者输入 q 暂时退出。
```

公钥在进入输入循环前只读取一次，Chat XDK runtime 只准备一次。错误 passcode 的重试只执行本地解锁，不重复请求 X API。空输入或 `q` 安全退出且不修改已有配置。

### X Chat 尚未初始化

如果账号没有可用 X Chat 密钥，显示：

```text
当前账号还没有可用的 X Chat 密钥。
请先在 X 中完成 X Chat 初始化，然后重新配置。
```

这属于账号状态，不描述为安装失败。

## 会话列表空页

真实接口可能返回 `data=[]`，同时返回 `next_token`、`has_more=true` 和 `has_message_requests=true`。因此空页绝不等于没有 X Chat。

规则：

- 空页且有新 `next_token` 时继续。
- 最多连续读取 3 个空页。
- 会话列表整轮最多 5 次请求。
- 重复 `next_token` 时立即停止。
- `has_more=true` 但没有 `next_token` 时停止。
- 找到配置上限数量的会话后立即停止。
- 空页不触发事件读取或公钥查询。
- 达到任一边界后标记扫描不完整。

用户可见覆盖说明统一为：

```text
X Chat 已按 X 返回顺序检查 N 个会话。
```

不再使用“最近 N 个会话”，因为会话列表实测没有 `updated_at`、`last_message_at` 或其他可验证的活动时间字段。

## 默认近期模式与主动扩展

普通日报默认只读取近期 X Chat：

- 时间窗口为最近 24 小时。
- 按 X 返回顺序最多检查 10 个会话。
- 每个会话最多读取 1 个事件页。
- 整轮最多发出 10 次事件请求。
- 解密后如果确认当前会话的最新可读消息早于时间窗口，立即停止，不再检查后续会话。

列表没有活动时间字段，因此不能在会话列表阶段提前判断新旧。只有成功读取并解密事件后，才能使用解密消息的 `created_at_msec` 判断是否越过窗口。没有可靠消息时间的会话不能作为停止依据；它标记为数据缺口，扫描继续到其他安全边界。

用户明确要求“查看更多私信”“多检查一些会话”或同等含义时，运行主动扩展模式：

- 时间窗口仍默认为最近 24 小时。
- 按 X 返回顺序最多检查 50 个会话。
- 每个会话最多读取 3 个事件页。
- 整轮最多发出 20 次事件请求。
- 确认当前会话最新可读消息早于窗口后仍立即停止。

用户明确要求“读取最近七天 Chat”时，将 X Chat 时间窗口改为 168 小时并使用主动扩展模式。此时只有确认最新可读消息早于七天窗口才停止。扩大 X Chat 范围不改变 Mentions 和 Timeline 的 24 小时窗口。

安全边界产生的是 `partial` 状态。默认近期模式不承诺检查全部会话；输出只报告实际检查数量，不将未检查内容推断为没有消息。

## 请求预算与 429

### 会话列表

- 每轮最多 5 次。
- 连续空页最多 3 次。
- 重复游标立即停止。
- HTTP 429 不重试。

### 会话事件

- 默认近期模式整轮最多 10 次；主动扩展模式最多 20 次。
- 根据响应头保留最后 5 次额度。
- 默认每个会话最多 1 页；主动扩展模式最多 3 页。
- 确认一个会话的最新可读消息早于当前窗口后立即停止。
- 没有下一页或已覆盖窗口时停止。
- HTTP 429 不重试。

### 公钥

- 按账号和用户 ID 缓存 24 小时。
- 只查询缺失或过期记录。
- 同一用户一轮最多查询一次。
- 解密验证失败时最多强制刷新一次。
- passcode 重试不重新查询公钥。

### 跨运行冷却

HTTP 429 后保存 owner-only 的 `.state/chat/rate_limits.json`。只允许以下字段：

```json
{
  "endpoint": "conversation_events",
  "retry_after_epoch": 1786347000
}
```

`endpoint` 只能是 `conversation_list`、`conversation_events` 或 `public_keys`。文件不得包含 API 路径、会话 ID、用户 ID、Token、正文、密文或响应体。

后续运行在发出 X Chat 请求前检查冷却记录。未到恢复时间时不调用 X，并沿用现有友好分类文案和预计恢复时间。恢复时间已过时删除对应记录并正常采集。无可用恢复时间的 429 只终止当前运行，不写永久冷却。

## 数据状态

Mentions、Timeline 和私信统一使用：

- `complete`：已覆盖本次声明范围，可以输出否定结论。
- `partial`：达到安全边界或字段缺失，只报告已获取内容和覆盖数量。
- `unavailable`：必要请求失败，不对该流做内容判断。

私信以下情况必须为 `partial`：默认近期模式未检查全部返回列表、列表仍有游标、连续空页达到上限、列表请求达到上限、重复游标、`has_more=true` 但缺少游标、事件预算耗尽、会话分页截断、会话缺少 ID或消息缺少可靠时间。

## 隐私与安全

- OAuth 继续只请求 `tweet.read users.read offline.access dm.read`。
- 不加入任何 write scope。
- passcode 不保存。
- 完整私信不进入长期日志。
- 冷却文件不保存资源标识或内容。
- 所有配置输入只在 Terminal 中进行。
- 所有 Agent 输出不得包含 Token、密钥、密文、会话 ID、用户 ID 或原始响应体。
- 安装仍使用 `curl ... | env ... sh`，不能要求最终用户进入仓库运行 Python。

## 测试与验收

### 输出

- 最终上下文不要求或暗示回复草稿。
- 用户要求发送时仍不生成回复文本。
- 输出段落和条数符合固定上限。
- `partial` 状态不产生“没有”“无需处理”等否定结论。

### Passcode

- 没有 passcode-backed key 时显示中文指引且无 traceback。
- 只有用户确认时才打开 X 消息页面。
- 错误 passcode 可以本地重试 3 次。
- 三次失败或用户退出后不写配置。
- 多次输入只发生一次公钥读取和一次 runtime 准备。
- 正确 passcode 保存 owner-only key blob，仍不保存 passcode。

### 空页与分页

- 第一页空、第二页有数据时成功返回会话。
- 连续 3 个空页后停止并标记 `partial`。
- 重复游标不形成死循环。
- `has_more=true` 且无游标时标记 `partial`。
- 空页不触发事件或公钥请求。

### 近期与扩展模式

- 普通日报最多检查 10 个会话、每个 1 页并使用 10 次事件预算。
- 普通日报确认第一个窗口外会话后不再请求后续会话。
- 没有可靠时间的会话不触发“旧会话停止”。
- 用户明确要求查看更多时允许 50 个会话、每个 3 页和 20 次事件预算。
- 用户要求最近七天时只改变 X Chat 窗口并使用扩展预算。
- 所有边界都产生真实检查数量和 `partial` 状态，不产生空收件箱结论。

### 429

- 三类 X Chat 429 都立即停止且不重试。
- 有 reset/retry-after 时写入脱敏冷却文件。
- 冷却期内不发出对应 API 请求。
- 冷却结束后删除记录并恢复请求。
- 冷却文件权限为 `0600`，父目录为 `0700`。

- 全部 twitter-digest 单元测试通过。
- Codex 和 Claude copy-install 测试通过。
- Shell 语法和 `git diff --check` 通过。
- 从正式标签下载的 `curl` 安装器可解析并默认锁定新版本。

## 发布版本

目标版本为 `v1.5.14-beta.13`。发布前使用模拟响应验证空页、重复游标、passcode 三次重试和跨运行冷却；真实账号只进行一次低请求会话列表验证，不用真实账号制造 429。

## 非目标

- 不增加 Activity API 或实时服务。
- 不建设长期处理状态数据库。
- 不自动识别 VIP 或分配 PR、法务、安全负责人。
- 不采集其他社交平台。
- 不在用户未主动要求时提高事件请求上限来换取完整性。
- 不自动操作 X 界面或接受消息请求。
